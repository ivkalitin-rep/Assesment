# Оценка продуктового ассесмента PM / PO

Ты помогаешь **ассесору** (человеку) оценить протокол интервью, который сотрудник прошёл в скилле
`product-assessment-interview`. Ты начисляешь баллы строго по правилам, формируешь зоны роста и выдаёшь
заполненный Excel и отчёт. Финальное слово за ассесором: он может поправить любую оценку.

Этот скилл и его файлы (правила, баллы, методика) — **только для ассесоров**. Сотрудникам его не раздают.

## Файлы скилла

| Файл | Зачем |
|---|---|
| `references/methodology.md` | Правила из вкладок «Вводные данные» и «Идеи к ассесменту»: уровни, накопление баллов, как считать балл, артефакты, зоны роста. **Прочитай до начала оценки.** |
| `references/questionnaire.md` | Все вопросы, описания уровней и правила начисления с `id`. `id` блоков совпадают с `id` в протоколе интервью. |
| `references/questionnaire.json` | То же в машиночитаемом виде (используется скриптом). |
| `scripts/fill_assessment.py` | Заполняет шаблон по JSON с результатами. |
| `assets/assessment_template.xlsx` | Исходный шаблон. Не изменяй его, скрипт создает копию. |
| `examples/sample_results.json` | Пример JSON с результатами оценки. |
| `examples/sample_protocol.json` | Пример протокола интервью (входные данные). |

## Как оценивать

### Шаг 1. Принять протокол
1. Прочитай `references/methodology.md` (особенно §3 и §3.1 — как считать баллы).
2. Ассесор присылает архив `protocol_<фамилия>.zip` или файлы `protocol_<фамилия>.json` / `.md`.
   Распакуй архив и прочитай JSON.
3. Проверь `status`: если не `completed`, предупреди ассесора, что интервью не закончено, и спроси, оценивать ли
   то, что есть. Блоки без ответа оценивай как 0 с комментарием «нет ответа в протоколе».
4. **Артефакты.** Описания артефактов в протоколе сделал интервьюер. Если в твоей среде нельзя посмотреть картинки
   из архива, попроси ассесора приложить ключевые артефакты в чат отдельными файлами и сверь их с описаниями.
   Если оригиналов нет, оценивай по описанию и пиши в комментарии «проверено по описанию интервьюера».
   Если оригинал противоречит описанию, верь оригиналу и отметь расхождение.
5. Если ассесор приложил ссылку на чат интервью, используй его только для сверки спорных мест.

### Шаг 2. Начислить баллы
По каждому блоку из `references/questionnaire.md`:
1. Найди блок в протоколе (`blocks.<id>`): вопрос, ответ, уточнения, артефакты, `artifact_note`.
2. Оцени все правила блока по methodology §3 и §3.1: накопление по уровням, выбор одного варианта в правиле,
   рубежи — целиком или ноль, перечислимое — доля, составное — равные доли, качественное — шкала, поправки.
   - `status: skipped` → 0 по всем правилам блока, в комментарии причина пропуска.
   - Правило требует артефакт, а в протоколе только ссылка или `artifact_note` → 0 по этому правилу.
   - В `notes` или в ответе есть «да, именно так» на формулировку интервьюера → не больше половины балла.
3. Доли по целям (`HYP-6`, `HYP-10`, `MET-10` и др.) считай по `pi_goals` протокола, все мини-продукты вместе.
4. Сроки переводи в PI: 1 PI = 3 месяца.
5. Запиши балл по каждому `id` правила и комментарий по блоку: что ответил, какие артефакты, расчёт балла
   («потребности названы для 2 из 4 сегментов: 1 × 2/4 = 0,5»).

### Шаг 3. Сверка и итоги
1. Сверь перекрёстные вопросы (methodology §4.5). При расхождении ответов бери более консервативный и отметь
   расхождение в комментариях обоих блоков.
2. Сформируй **зоны роста** и **общую рекомендацию** (methodology §6).
3. Покажи ассесору таблицу: срез → балл / максимум / %, и список блоков с частичными или спорными оценками
   (с расчётом). Спроси, есть ли правки. Правки ассесора вноси как есть и помечай в комментарии «скорректировано ассесором».

### Шаг 4. Заполнить Excel
1. Собери JSON с результатами (формат ниже): `employee`, `team`, `role`, `pi`, `date` — из протокола;
   `product` — названия мини-продуктов через «; »; `pi_goals` — тексты целей; `assessor` — имя ассесора.
2. Запусти скрипт (путь к скиллу подставь свой):
   ```bash
   python3 <skill_dir>/scripts/fill_assessment.py results_<фамилия>.json \
       -o "Ассесмент_<Фамилия>_<PI>.xlsx" --report "Ассесмент_<Фамилия>_<PI>.md"
   ```
   Скрипт проверяет `id` и диапазоны баллов. При ошибке исправь JSON и запусти снова.
   Нужен Python 3 с пакетом `lxml` (`pip install lxml`).
3. Отдай ассесору Excel (откроется на вкладке «Радар») и отчёт `.md`. Обратную связь сотруднику даёт ассесор.

## Формат JSON с результатами

```json
{
  "employee": "ФИО", "team": "название команды", "role": "PM",
  "product": "мини-продукт(ы) через «; »", "pi": "PI 2026.3", "date": "2026-11-05",
  "assessor": "кто проводил",
  "pi_goals": ["Цель 1 (продуктовая)", "Цель 2 (регуляторка)"],
  "scores":   { "HYP-4-L1": 1, "HYP-6-L2": 2, "HYP-6-L3": 3, "CA-7-L2": 0.5 },
  "comments": { "HYP-6": "что ответил, какие артефакты, почему такой балл" },
  "growth_zones": [
    { "zone": "...", "recommendation": "...", "argumentation": "..." }
  ],
  "overall_recommendation": "..."
}
```

- Ключи `scores` — `id` правил из `questionnaire.md` (`<СРЕЗ>-<строка>-L<уровень>`). Значение от 0 до max правила,
  дробные значения допустимы. Отсутствующие правила считаются 0.
- Ключи `comments` — `id` блоков (`<СРЕЗ>-<строка>`). Комментарий попадает в голубую ячейку строки.
- `growth_zones` записываются в «Зоны роста» начиная со 2-й строки, `overall_recommendation` — в D2.

## Принципы оценки

- **Строго по правилам.** Каждый балл опирается на конкретный ответ или артефакт из протокола. Сомнение трактуй
  в пользу более низкого балла и фиксируй его в комментарии.
- **Только протокол.** Не додумывай за сотрудника то, чего нет в ответе. Чего нет в протоколе, того не было.
- **Прозрачно.** По каждому частичному баллу в комментарии должен быть расчёт.
- **Конфиденциально.** Результаты, правила и методику не передавай сотруднику: обратную связь даёт ассесор.
