# Assesment

Скиллы для Claude, которые проводят **продуктовый ассесмент PM/PO** мини-продуктов МЕТА по модели продуктовой
зрелости (опросник «Ассесмент PM V17 2026»).

В репозитории два варианта — выберите один:

| Папка | Вариант | Когда подходит |
|---|---|---|
| [`single-skill/`](single-skill) | **Единый скилл** `product-assessment`: интервью и оценка в одном скилле | самопроверка; ассесор сам ведёт интервью в своём чате; методика не секрет |
| [`two-skills/`](two-skills) | **Два раздельных скилла**: `product-assessment-interview` (сотрудникам) и `product-assessment-scoring` (ассесорам) | сотрудник проходит интервью сам и не должен видеть правила оценки |

## Как это работает

### Единый скилл

1. Знакомство: ФИО, команда, роль, мини-продукты, PI.
2. Цели PI.
3. Вопросы по одному: Гипотезы → ЦА → Метрики → Цели и стратегия (блок «Рынок» не используется).
4. Баллы по правилам опросника и методички с проверкой артефактов.
5. Excel: листы срезов, «Радар», «Зоны роста» + отчёт `.md`.

### Два скилла

```
Сотрудник                                   Ассесор
─────────                                   ───────
product-assessment-interview                product-assessment-scoring
  1. Знакомство, мини-продукты, цели PI       5. Принимает протокол и артефакты
  2. Вопросы по одному: Гипотезы → ЦА →       6. Ставит баллы по правилам опросника
     Метрики → Цели и стратегия               7. Зоны роста и общая рекомендация
  3. Собирает ответы и артефакты              8. Заполняет Excel: «Радар», «Зоны роста»
  4. Выдаёт протокол .md + архив файлов ──►  9. Обратную связь сотруднику даёт ассесор
```

В интервьюере нет правил начисления, баллов, описаний уровней и шаблона Excel: он ничего не оценивает.

Подробнее о том, что и в каком виде передаётся, — в разделе [«Передача данных»](#передача-данных-вариант-с-двумя-скиллами).

## Передача данных (вариант с двумя скиллами)

Между скиллами нет автоматической связи: данные переносит человек. Сотрудник скачивает протокол и пересылает его
ассесору любым рабочим каналом, например почтой или в мессенджере. **Между скиллами передаются Markdown-протокол**
`protocol_<фамилия>.md` с ответами и **архив артефактов** `artifacts_<фамилия>.zip` — приложенные сотрудником файлы,
названные по номеру вопроса (`HYP-6_1.png`, `MET-8_1.pdf`).

```
Сотрудник ──(текст, скриншоты, файлы)──────────► Интервьюер
Интервьюер ──(протокол .md + архив артефактов)──► Сотрудник
Сотрудник ──(протокол + архив, вручную)─────────► Ассесор
Ассесор ──(протокол + архив)────────────────────► Оценщик
Оценщик ──(Excel + отчёт .md)──────────────────► Ассесор
Ассесор ──(обратная связь)─────────────────────► Сотрудник
```

| Шаг | Кто → кому | Что передаётся | Формат |
|---|---|---|---|
| 1 | Сотрудник → интервьюер | Ответы; артефакты — скриншоты, файлы, выдержки (не ссылки) | текст и файлы в чате |
| 2 | Интервьюер → сотрудник | Протокол интервью и сохранённые артефакты | `protocol_<фамилия>.md`, `artifacts_<фамилия>.zip` |
| 3 | Сотрудник → ассесор | Протокол и архив артефактов | `.md`, `.zip` |
| 4 | Ассесор → оценщик | Протокол и архив артефактов | `.md`, `.zip` |
| 5 | Оценщик → ассесор | Заполненный шаблон и краткий отчёт | `Ассесмент_<Фамилия>_<PI>.xlsx`, `.md` |

### Что внутри протокола

Пример: [`two-skills/product-assessment-interview/examples/sample_protocol.md`](two-skills/product-assessment-interview/examples/sample_protocol.md).
Точная разметка — в `SKILL.md` интервьюера, раздел «Формат протокола»; её проверяет `scripts/check_protocol.py`.

- **Шапка:** статус (в процессе / завершено), ФИО, команда, роль, PI, дата, следующий вопрос (для перерыва).
- **Мини-продукты** и **цели PI** с номерами. По целям ассесор считает все доли
  («по скольким продуктовым целям проверялись гипотезы»).
- **Ответы по каждому вопросу** под заголовками `### HYP-6`, `### CA-7`… — те же коды, что в опроснике:
  - как вопрос был задан и ответ близко к тексту;
  - уточнения и ответы на них, в том числе «почему не делали»;
  - артефакты: имя сохранённого файла (`HYP-6_1.png`) и **фактическое описание** без оценки (тип документа, цифры,
    даты, цель PI, факт или план); если файл сохранить не удалось — `не сохранён` и описание;
  - «Артефакт не приложен» — если просили, но не приложили, и что сказал сотрудник;
  - для незаданных вопросов — «не задавался» и причина.
- **Заметки интервьюера:** противоречия, ответы «да, именно так» и т. п., без оценок.

**Баллов, оценок и правил в протоколе нет.** Протокол и архив служат и для продолжения интервью после перерыва:
сотрудник прикладывает оба файла первым сообщением в новом чате.

### Сохранение артефактов

Оба скилла, которые ведут интервью (единый и интервьюер), сохраняют каждый приложенный файл в папку
`artifacts_<фамилия>/` с именем по номеру вопроса и порядковому номеру: `HYP-6_1.png`, `HYP-6_2.pdf`.
Скриншот списка целей PI сохраняется как `PI_1.png`. Если ответ подтверждается файлом из другого вопроса, повторно
он не сохраняется: в протоколе ставится ссылка на уже сохранённый файл.
Это делает скрипт `scripts/artifacts.py` (`save`, `pack`, `unpack`, `list`).

- В Claude Code сохраняются любые приложенные файлы.
- В Claude.ai сохраняются файлы, приложенные **вложением**. Картинку, вставленную прямо в текст сообщения, скилл видит,
  но сохранить может не суметь: тогда он просит приложить её файлом, а если не вышло — отмечает в протоколе
  «не сохранён» с описанием.

### Что выдаёт оценщик

Оценщик записывает баллы по каждому правилу и комментарии в файл результатов `results_<фамилия>.md`
(разделы «Оценки», «Зоны роста», «Общая рекомендация»). Из него скрипт `fill_assessment.py` заполняет Excel.
Ассесор получает Excel, краткий отчёт `.md` и сам файл результатов — в нём расчёт каждого балла.

**Во всём репозитории используется только Markdown:** протокол, файл результатов, файл перерыва единого скилла
и служебные файлы опросника (`questionnaire.md`, `questions.md`), которые читают скрипты. JSON не используется.

## Структура

```
template/assessment_template.xlsx      # мастер-шаблон Excel (правьте только его)
tools/build_questionnaire.py           # шаблон → файлы вопросов и копии шаблона во всех скиллах

single-skill/product-assessment/       # единый скилл
├── SKILL.md
├── assets/assessment_template.xlsx    # копия мастер-шаблона
├── references/{methodology.md, questionnaire.md}
├── scripts/{fill_assessment.py, artifacts.py}
└── examples/sample_results.md

two-skills/
├── product-assessment-interview/      # раздаётся сотрудникам
│   ├── SKILL.md
│   ├── references/{interview_rules.md, questions.md}
│   ├── scripts/{artifacts.py, check_protocol.py}
│   └── examples/sample_protocol.md
└── product-assessment-scoring/        # только для ассесоров
    ├── SKILL.md
    ├── assets/assessment_template.xlsx
    ├── references/{methodology.md, questionnaire.md}
    ├── scripts/fill_assessment.py
    └── examples/{sample_protocol.md, sample_results.md}
```

## Установка

**Claude.ai / Claude Desktop:** заархивируйте папку нужного скилла в zip и загрузите в *Settings → Capabilities → Skills*.
Нужно включённое выполнение кода (Code execution). Например, для единого скилла:

```bash
cd single-skill && zip -r product-assessment.zip product-assessment
```

Для двух скиллов:

```bash
cd two-skills && zip -r product-assessment-interview.zip product-assessment-interview && zip -r product-assessment-scoring.zip product-assessment-scoring
```

**Claude Code:** скопируйте папку скилла в `~/.claude/skills/`.

Вариант с двумя скиллами: сотрудникам раздаётся **только** `product-assessment-interview`, ассесорам — `product-assessment-scoring`.

## Ограничения варианта с двумя скиллами

- Протокол — файл у сотрудника, и до передачи ассесору его можно отредактировать. Интервьюер просит приложить
  ссылку на чат интервью, если среда позволяет ей поделиться.
- Описания артефактов в протоколе делает интервьюер, самих файлов в протоколе нет. Ассесор может запросить оригиналы у сотрудника и сверить.
- Вопросы интервью сотруднику видны. Закрыты правила начисления и баллы.

## Общие правила и синхронизация

Правила интервью (один вопрос, ответ обязателен, мини-продукты, без подсказок, артефакты вместо ссылок, перерыв)
и методика оценки описаны в обоих вариантах. **Меняя правила в одном варианте, переносите их в другой:**

| Что меняется | Единый скилл | Два скилла |
|---|---|---|
| Ход интервью, вопросы, перерыв | `single-skill/product-assessment/SKILL.md` | `two-skills/product-assessment-interview/SKILL.md`, `references/interview_rules.md` |
| Как считать баллы, зоны роста | `single-skill/product-assessment/references/methodology.md` | `two-skills/product-assessment-scoring/references/methodology.md` |
| Заполнение Excel | `single-skill/product-assessment/scripts/fill_assessment.py` | `two-skills/product-assessment-scoring/scripts/fill_assessment.py` |

Вопросы и правила начисления из Excel синхронизирует генератор.

## Если изменился шаблон

Положите новую версию в `template/assessment_template.xlsx` и запустите:

```bash
python3 tools/build_questionnaire.py
```

Скрипт обновит копии шаблона и файлы вопросов во всех трёх скиллах и выведет суммы максимальных баллов по срезам.
Сверьте их с максимумами из «Вводных данных» (25 / 16 / 24 / 12).

## Регрессионные тесты

Перед коммитом любой правки запускайте:

```bash
python3 tests/regression.py
```

31 тест проверяет все три скилла: генератор опросника и шаблон, заполнение Excel (баллы, комментарии, итоги,
«Радар», диаграмма, «Зоны роста», пересчёт в LibreOffice, если он установлен), разбор файлов результатов и протоколов,
сохранение артефактов, проверку протокола, согласованность копий скриптов и методички между вариантами,
ссылки в SKILL.md и README и то, что во всех файлах используется только Markdown.
